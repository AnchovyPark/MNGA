## 2. 고정 공식 한계 = regime bias → ML 필연 (핵심 규명)
- 사용자 반복 시도(가운데 op 뽑기, 대칭 평균 등) 전부 **telescope와 대수적 동치**임을 증명. U,W₂,W₃로는 **양쪽-문맥 op latency를 유일하게 못 뽑음(under-determined)** — 쌍 overlap을 두 op에 나누는 게 안 정해짐.
- **결정적: 1B(과소 0.97~0.985) vs 8B(과대 1.03) — 오차 부호 반대.** 대칭공식은 8B 개선(1.014)하나 1B 악화(0.898). **어떤 고정 공식도 regime 양쪽 못 맞춤** → feature 기반 ML만 가능(부호 뒤집힘을 feature가 학습).
- 데이터: 1B·8B @512 chained n-gram. data_sizesweep 등.

## 3. kernel-based 전환 (단일 matmul)
- atom=generic matmul(M,K,N). LLM 대표 shape 50개(seq5×shape10) 측정 → **latency=f(shape) leave-one-out MAPE ~9%** (Ridge 9.5, GBM 8.9). flops 지배(0.94). 코드 kernel_measure_30.py, data_kernels_single.txt.
- ⚠️ **거대 matmul(2048,4096,14336=240GFLOP)은 device-cycle 프로파일러 실패**: 타일 수십개로 쪼개져 cycle_actual=0. 커널 자체는 정상(host=1426us). → 큰 op은 host 타이밍 필요.

## 4. overlap 경향 (matmul 쌍, weight-prefetch + fusion)
- 연쇄 pair A→B overlap = U(A)+U(B)−W₂. **shape 의존(상수 아님)**: A compute 크고 B weight 클수록 overlap↑ = **weight-prefetch(A 계산 중 B weight 로드)**. 작은 A는 overlap floor. data_matmul_pairs.txt.
- **사이 연산 효과 (data_midop_overlap.txt, gate→down 모양)**:
  - **silu: overlap 그대로**(69.0→68.7 / 129.9→130.5) = **완전 fusion**(활성화는 HBM 안 건드림).
  - **rmsnorm: overlap ~19us 감소**(69→50.5 / 130→110.9) = **부분 barrier**(중간값 일부 HBM 강제 + norm sync).
  - → 사용자 HBM 통찰 확인. gate→silu→down은 full overlap, o→norm→gate는 reduced.

## 6. 측정 방법 caveat (누적)
- **device-cycle 프로파일러**(정밀, floor 없음): 큰 그래프/거대 op에서 cycle_actual=0 캡처 실패. min 취하면 0-task에 오염 → 큰 op은 wall-span(begin/end)도 지저분.
- **host stream-sync**(robust, 모든 크기): op당 ~40us floor. 큰 op엔 무시가능, 작은 op·overlap엔 bias.
- **클럭 불확실(~1.5~2GHz)** → 시간 변환 애매. **cycle끼리 비교로 회피.**
- **긴 프로세스 degrade** → window마다 fresh 프로세스 필수.
