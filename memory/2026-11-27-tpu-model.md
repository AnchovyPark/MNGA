- 인자 값은 `layer.py`와 같다: layer i의 parameter = `layer_params(seed=i+1)` (= `stack_params(seed=0)`의 i번째).
  host(CPU backend)에서 만들어 두고 측정마다 device_put 한다. scan의 [n, ...] 배열도 host에서 쌓는다
  (device에서 `jnp.stack`하면 8B 32층은 weight가 두 벌 28 GB가 되어 chip 하나에 안 들어간다).
- 입력 사본: x(또는 tokens)만 사본 2개 (지시서 §3). x·rope 표·embed 등의 seed는 mlib에 고정 (값은 latency와 무관).
- `_info.txt`의 `n_ops`는 HLO op 종류 수다 (op 개수 아님). `peak_GiB`는 process 안 누적 peak.

## Step 1 확인 (`check_cpu.py`, `jobs_step1.txt` → `data_step1_tpu_v4.txt`, `analyze_step1.py` → `analyze_step1.log`)

1. CPU 작은 크기 2종 (`check_cpu.log`): unroll = scan = layer 하나씩 부른 값 = emb+stack+head 직접 조립.
   bf16 상대오차 max|a−b|/max|b| ≤ 2.5% (random N(0,1) weight라 x가 1e4~1e5로 커진다. fusion 경계가 달라 반올림만 다름),
   model logits는 조립과 오차 0.
2. TPU layer 1개 vs Module 2 L16 full (`module2/data_layerpred_tpu_v4.txt` l1_meas, copies2):
   `layer.make_layer`에 x·weight 모두 사본 2개(Module 2 window와 같은 입력 방식) → 1B·3B·8B × seq 4 **12점 모두 ±0.1% 안**.
3. 8B 32층 `make_model` (vocab 128256): chip 하나에 올라간다. argument 14.96 GiB, process peak 15.1~15.5 GiB (HBM 32 GiB).
   compile: unroll 13.7~14.4 s, scan 3.3~3.6 s. 값: unroll 35.27 ms (seq 512) / 151.8 ms (2048), scan 37.26 / 152.5 ms.
4. weight 사본 artifact (N=1, x만 사본 vs weight도 사본): **같은 weight buffer를 반복하면 1.6~17% 빠르게 잡힌다.**

| N=1 artifact = 1 − unroll/unroll_w2 | seq 128 | 512 | 1024 | 2048 |
|---|---|---|---|---|
| 1B | 17.1% | 6.9% | 3.7% | 1.6% |
| 3B | 15.7% | 7.2% | 4.4% | 2.0% |
| 8B | 16.9% | 8.3% | 4.7% | 2.3% |

   - 차이의 절대값이 seq와 거의 무관하다: 1B 25~34 µs, 3B 41~50 µs, 8B 99~116 µs. 8B 99 µs ≈ 117 MB / 1.2 TB/s ≈ weight 배열 1개
     (wg/wu 4096×14336 bf16 = 112 MiB ≤ 128 MiB) → cross-program prefetch가 weight 하나를 CMEM에 미리 올려 두는 Module 1 Step 1과 같은 artifact.
   - program당 weight 1개라면 N에 무관한 상수다 → Step 2의 맨 끝에 N=2도 weight 사본으로 재서 확인한다.
     상수라면 L(N) 차이(marginal)는 영향이 없고 L(1)과 ρ의 분모만 작아진다.
   - scan N=1 vs unroll N=1: −4~+11% (seq 128에서 scan이 느리다).
