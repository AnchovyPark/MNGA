   model logits는 조립과 오차 0.
2. TPU layer 1개 vs Module 2 L16 full (`module2/data_layerpred_tpu_v4.txt` l1_meas, copies2):
   `layer.make_layer`에 x·weight 모두 사본 2개(Module 2 window와 같은 입력 방식) → 1B·3B·8B × seq 4 **12점 모두 ±0.1% 안**.
3. 8B 32층 `make_model` (vocab 128256): chip 하나에 올라간다. argument 14.96 GiB, process peak 15.1~15.5 GiB (HBM 32 GiB).
   compile: unroll 13.7~14.4 s, scan 3.3~3.6 s. 값: unroll 35.27 ms (seq 512) / 151.8 ms (2048), scan 37.26 / 152.5 ms.
4. weight 사본 artifact (N=1, x만 사본 vs weight도 사본): **같은 weight buffer를 반복하면 1.6~17% 빠르게 잡힌다.**

| N=1 artifact = 1 − unroll/unroll_w2 | seq 128 | 512 | 1024 | 2048 |

   - program당 weight 1개라면 N에 무관한 상수다 → Step 2의 맨 끝에 N=2도 weight 사본으로 재서 확인한다.
     상수라면 L(N) 차이(marginal)는 영향이 없고 L(1)과 ρ의 분모만 작아진다.

## Step 2 L(N) (`jobs_step2.txt` → `data_stack_tpu_v4.txt` 168행, 실패 0; `analyze_stack.py` → `analyze_stack.log`)

make_stack, x만 사본 2개. 1B N ∈ {1,2,3,4,8,16}, 3B {…,28}, 8B {…,32} × seq 4 × unroll·scan. 측정 8분 (chip 4).

| unroll ρ = (L(2)−L(1))/L(1) | seq 128 | 512 | 1024 | 2048 |
|---|---|---|---|---|
| 1B | 0.896 | 0.940 | 0.962 | 0.985 |
| 3B | 0.867 | 0.906 | 0.930 | 0.965 |
| 8B | 0.913 | 0.931 | 0.879 | 0.916 |

- **unroll: 구간 marginal이 N=2부터 거의 일정하다** (대부분 ρ의 ±5% 안. 예외: 1B seq 128 0.90~1.00, 3B seq 1024의 3–4 구간 1.00, 8B seq 1024 0.88→0.94).
  RNGD(N=2부터 0.86)와 같은 모양, 값은 0.87~0.99로 RNGD보다 겹침이 작다.
- weight 사본 artifact는 N에 무관한 상수다: N=2에서도 L_w2 − L = 1B 25~33 µs, 8B 99~115 µs (N=1과 같음). → marginal은 영향 없음.
- **scan: L(2)−L(1)만 튀고 N=3부터 일정하다.** 1B·3B에서 ρ 1.13~1.69, N≥3 marginal/L(1) = 1.04~1.28 (> 1, 겹침 없음 + loop 비용). 8B는 ρ 0.77~0.92, N≥3 0.89~0.97.
- scan/unroll − 1: N=1에서 −4~+11%, N≥2에서 1B·3B seq 128 +27~46%, seq 2048 +3~7%, 8B −1~+7%. scan은 작은 model·짧은 seq에서 확실히 느리다.

### trace: 겹침은 어디서 생기나 (`trace_stack.py` → `trace_{8B_512,8B_2048,1B_128}_unroll.log`, `trace_1B_512_scan.log`)

- core0 'XLA Ops' 합 = sync_min (op끼리 시간상 겹치지 않는다). 겹침은 **'Async XLA Ops'의 비동기 weight prefetch**다.
- unroll HLO: layer i ≥ 1의 weight를 `slice-start → slice-done → ConcatBitcast`로 CMEM(S(3))에 미리 옮긴다.
  8B seq 512 N=3: L1·L2의 wq, wk, wv, wo, wu. 1B seq 128 N=3: L1 wk, wv, wg, wd, wu / L2 wk, wv, wo, wg, wd. 첫 layer(L0)의 weight는 program 안에서는 prefetch되지 않는다
  (cross-program prefetch 1개 = Step 1 artifact, `copy-start ... cross_program_prefetch_index=0`, 보통 L0.wg 또는 wu).
- 시점 (8B seq 512 N=2): **다음 layer의 attention weight(wq·wk·wv·wo) 복사는 앞 layer의 MLP up·down gemm 동안** 돈다.
  다음 layer의 MLP weight(wu) 복사는 그 layer의 attention(qk·av fusion) 동안 돈다.
- 효과: 두 번째 layer의 gemm이 CMEM에서 weight를 읽어 짧아진다. wq 77→66, wk 29→17, wv 28→17, wo 79→67 µs (8B seq 512).
  layer 1개 앞만 prefetch한다 (layer i의 weight는 layer i−1 동안) → marginal이 N=2부터 일정한 이유.
- scan: N=3 이상에서 program 안 weight prefetch 0개, cross-program prefetch도 없다. loop 경계를 넘어 prefetch하지 않는다 → scan marginal ≥ L(1).
  N=2 scan은 prefetch 3개가 남아 있다 (XLA가 trip count 2 loop를 다르게 다룸) → L(2)만 튄다.

- scan은 ρ를 unroll로 학습했고(Step 4는 unroll만) scan의 layer 1개 값도 다르므로 맞지 않는다 (scan용 ρ는 재지 않았다).

## 정리

1. TPU layer 사이 겹침 = XLA가 다음 layer의 weight를 앞 layer 계산 중에 CMEM으로 비동기 prefetch. **바로 앞 layer까지만** (RNGD와 같은 결론). unroll에서만 생기고 scan은 loop 경계를 넘지 않는다.
2. marginal/L(1) = 0.87~0.99 (Step 2 세 model; Step 4 크기 10종은 0.77~1.07) — RNGD 0.86보다 겹침이 작다. 1B·3B는 seq가 길수록 1에 가깝다 (계산이 커져 weight load 비중이 작다). 8B는 0.88~0.93으로 seq와 뚜렷한 관계가 없다.
3. L(1)+(n−1)(L(2)−L(1)): unroll 1.9% (L(n)), full model 2.0%. scan은 L(3)·L(4)를 써야 한다.
4. 완전 bottom-up full model (Module 1 U → Module 2 n-gram layer → ρ̂ → model): unroll 7.2% (seq ≥ 512는 5.4%), 단순 합 6.1%(측정 L(1) 사용)보다 크다.
   단순 합은 측정 L(1)을 쓰므로 공정한 비교는 l1_meas 기준 4.3% vs 6.1%.

caveat: batch 1, prefill만, chip 1개. weight는 layer마다 다른 buffer지만 같은 buffer로 반복 측정 (첫 weight 1개 cross-program prefetch artifact, 8B ≈ 100 µs, 1B ≈ 28 µs → full model에서 0.1~0.9%, seq 128에서 가장 크다).
