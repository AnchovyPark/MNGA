지시서 `TPU_NEXT_MODEL.md`. 용어는 `TERMS.md`. code·data는 `profiling/tpu_v4/model/`. 측정 규칙은 `module2/README.md`.

## 결론

1. **layer 사이 overlap은 바로 앞 layer까지만 닿는다** (RNGD와 같은 결론). XLA가 다음 layer의 weight를 앞 layer 계산 중에 chip 안 memory(CMEM)로 비동기 복사한다. unroll에서만 생기고 scan에서는 생기지 않는다.
2. 추가 layer 비율은 0.87~0.99다 (1B·3B·8B, unroll). RNGD(0.86)보다 overlap이 작다.
   예: 8B seq 512에서 lat(1 layer) = 1088 µs, 추가 layer latency = 1013 µs (비율 0.931), lat(32 layer) 측정 33023 µs.
3. `lat(1 layer) + (N − 1) × 추가 layer latency`로 쌓은 latency 예측: unroll 오차 1.9% (최대 6.9%). layer latency × N은 6.2%.
   scan은 2 layer만 튀므로 3 layer부터 일정한 값을 써야 한다 (오차 0.18%).
4. model latency: 쌓은 latency 예측 + 측정 embedding·head latency → unroll 오차 2.0% (최대 5.1%). layer latency × n은 6.1%.
5. **shape만으로 예측한 model latency: unroll 오차 7.2% (최대 20%), seq ≥ 512만 보면 5.4%.**
   오차의 반은 예측 추가 layer 비율, 반은 예측 layer latency에서 온다. 가장 나쁜 곳은 seq 128.
6. head latency(lm_head, 마지막 token 1개)는 1B에서 1.1 ms로, 1B seq 128 model latency의 35%다.

## Step 1 확인 (`check_cpu.py`, `jobs_step1.txt` → `data_step1_tpu_v4.txt`, `analyze_step1.py` → `analyze_step1.log`)

1. CPU 작은 크기 2종 (`check_cpu.log`): unroll = scan = layer를 하나씩 부른 값 = embedding·stack·head를 직접 이은 값.
   bf16 상대 차이 max|a−b|/max|b| ≤ 2.5% (random N(0,1) weight라 activation이 1e4~1e5로 커진다. fusion 경계가 달라 반올림만 다름).
2. TPU layer latency vs Module 2 VM의 측정 layer latency (`module2/data_layerpred_tpu_v4.txt`의 `l1_meas_us`):
   `layer.make_layer`에 입력·weight 모두 번갈아 쓰기(Module 2와 같은 방식) → 1B·3B·8B × seq 4, **12점 모두 ±0.1% 안**. 예: 1B seq 512 362.3 vs 362.5 µs.
3. 8B 32 layer `make_model` (vocab 128256): chip 하나에 올라간다. argument 14.96 GiB, process peak 15.1~15.5 GiB (HBM 32 GiB).
   compile: unroll 13.7~14.4 s, scan 3.3~3.6 s. model latency: unroll 35.27 ms (seq 512) / 151.8 ms (2048), scan 37.26 / 152.5 ms.
4. weight 반복 효과 (1 layer, weight 같은 buffer 반복 vs weight도 번갈아 쓰기): **같은 weight를 반복하면 1.6~17% 빠르게 나온다.**

| 1 − lat(1 layer) / lat(1 layer, weight도 번갈아) | seq 128 | 512 | 1024 | 2048 |
|---|---|---|---|---|
| 1B | 17.1% | 6.9% | 3.7% | 1.6% |
| 3B | 15.7% | 7.2% | 4.4% | 2.0% |
| 8B | 16.9% | 8.3% | 4.7% | 2.3% |

   - 차이(µs)는 seq와 거의 무관하다: 1B 25~34, 3B 41~50, 8B 99~116 µs. 8B 99 µs ≈ 117 MB / 1.2 TB/s ≈ weight 배열 1개
     (`wg`/`wu` 4096×14336 bf16 = 112 MiB ≤ 128 MiB). HLO의 `copy-start ... cross_program_prefetch_index=0`이 첫 layer의 weight 하나를
     다음 실행용으로 CMEM에 올려 둔다 (Module 1 Step 1과 같은 현상).
   - 2 layer에서도 차이가 같다 (1B 25~33, 8B 99~115 µs) → N에 무관한 상수. 추가 layer latency에는 영향이 없고 lat(1 layer)만 작아진다.

## Step 2 N layer latency (`jobs_step2.txt` → `data_stack_tpu_v4.txt` 168행, 실패 0; `analyze_stack.py` → `analyze_stack.log`)

`make_stack`, 입력만 번갈아 쓰기. 1B N ∈ {1,2,3,4,8,16}, 3B {…,28}, 8B {…,32} × seq 4 × unroll·scan. 측정 8분 (chip 4개).

| unroll 추가 layer 비율 | seq 128 | 512 | 1024 | 2048 |
|---|---|---|---|---|
| 1B | 0.896 | 0.940 | 0.962 | 0.985 |
| 3B | 0.867 | 0.906 | 0.930 | 0.965 |
| 8B | 0.913 | 0.931 | 0.879 | 0.916 |

- **unroll: 추가 layer latency가 2 layer부터 거의 일정하다** (구간별 값이 대부분 ±5% 안. 예외: 1B seq 128은 lat(1 layer)의 0.90~1.00배로 흔들림,
  3B seq 1024의 3→4 구간 1.00배, 8B seq 1024는 0.88배 → 0.94배).
- 1B·3B는 seq가 길수록 비율이 1에 가깝다 (계산이 커져 weight load 비중이 작다). 8B는 0.88~0.93으로 seq와 뚜렷한 관계가 없다.
- **scan: 2 layer만 튀고 3 layer부터 일정하다.** 1B·3B에서 추가 layer 비율 1.13~1.69, 3 layer 이후 추가 layer latency는 lat(1 layer)의 1.04~1.28배 (overlap 없음 + loop 비용).
  8B는 비율 0.77~0.92, 3 layer 이후 0.89~0.97배.
- scan / unroll − 1: 1 layer에서 −4~+11%, 2 layer 이상에서 1B·3B seq 128 +27~46%, seq 2048 +3~7%, 8B −1~+7%. 작은 model·짧은 seq에서 scan이 확실히 느리다.

### layer 사이 overlap은 어디서 생기나 (`trace_stack.py` → `trace_8B_512_unroll.log`, `trace_8B_2048_unroll.log`, `trace_1B_128_unroll.log`, `trace_1B_512_scan.log`)

- core 0의 'XLA Ops' 시간 합 = TPU 실행 시간이다. 계산 op끼리는 겹치지 않는다. overlap은 **'Async XLA Ops'에 있는 weight 비동기 복사**다.
- unroll HLO: 두 번째 layer부터 weight를 `slice-start → slice-done → ConcatBitcast`로 CMEM(S(3))에 미리 복사한다.
  8B seq 512, 3 layer: layer 1·2의 `wq`, `wk`, `wv`, `wo`, `wu`. 1B seq 128, 3 layer: layer 1의 `wk`, `wv`, `wg`, `wd`, `wu`, layer 2의 `wk`, `wv`, `wo`, `wg`, `wd`.
  첫 layer의 weight는 program 안에서 미리 복사되지 않는다 (위 Step 1의 다음 실행용 복사 1개만 있다).
- 시점 (8B seq 512, 2 layer): **다음 layer의 attention weight(`wq`·`wk`·`wv`·`wo`) 복사는 앞 layer의 MLP(up·down gemm) 동안** 돈다.
  다음 layer의 MLP weight(`wu`) 복사는 그 layer의 attention(qk·av fusion) 동안 돈다.
- 효과: 두 번째 layer의 gemm이 CMEM에서 weight를 읽어 짧아진다. 8B seq 512에서 `q` 77→66, `k` 29→17, `v` 28→17, `o` 79→67 µs.
  layer i의 weight는 layer i−1 동안만 복사된다 → 추가 layer latency가 2 layer부터 일정한 이유.
- scan: 3 layer 이상에서 program 안 weight 복사 0개, 다음 실행용 복사도 없다. loop 경계를 넘어 복사하지 않는다 → 추가 layer latency ≥ lat(1 layer).
  2 layer scan은 복사 3개가 남아 있다 (XLA가 반복 2번짜리 loop를 다르게 다룬다) → 2 layer만 튄다.

## Step 3 쌓은 latency 예측 (N ∈ {8, 16, n}, `analyze_stack.log` 끝)

k = 추가 layer latency를 몇 layer부터 재서 쓰는지. k=1: `lat(1 layer) + (N−1)(lat(2 layer) − lat(1 layer))` (지시서 §2 식).
k=2·3: `lat(k layer) + (N−k)(lat(k+1 layer) − lat(k layer))`. k=4: 4→8 구간 평균 사용.

| 오차 (최대) | layer latency × N | k=1 | k=2 | k=3 | k=4 |
|---|---|---|---|---|---|
| unroll (32점) | 6.2% (16%) | **1.9% (6.9%)** | 1.3% (5.0%) | 1.3% (4.8%) | 0.5% (3.6%, 20점) |
| scan (32점) | 7.1% (22%) | 9.5% (28%) | 3.1% (16%) | **0.18% (0.6%)** | 0.13% |

- unroll: 지시서 식(k=1)으로 1.9%. 가장 나쁜 곳은 1B seq 128 (−6.9%).
- scan: k=1은 2 layer가 튀어서 깨진다 (1B·3B seq 128에서 +20~28%). scan은 k=3이어야 한다.

## Step 4 추가 layer 비율, 안 본 model 크기 (`jobs_step4.txt` → `data_rho_meas_tpu_v4.txt` 160행, 실패 0; `analyze_rho.py` → `analyze_rho.log`, `data_rho_tpu_v4.txt`)

model 크기 10종 × seq 4 × N {1, 2, 4}, unroll. 1 layer는 weight도 번갈아 쓴 측정을 같이 했다.
Step 2와 겹치는 3 크기는 다시 잰 값이다 (36점, 최대 차이 0.08%).

추가 layer 비율을 두 기준으로 낸다.
- a (`rho`): 지시서 정의. 분모 = 입력만 번갈아 쓴 lat(1 layer).
- b (`rho_w2`): 분모 = weight도 번갈아 쓴 lat(1 layer). Module 2의 예측 layer latency가 이 방식으로 잰 값을 학습했으므로 Step 6에서 짝이 맞는 것은 b다.

| seq | a 평균 (최소~최대) | b 평균 (최소~최대) |
|---|---|---|
| 128 | 0.897 (0.77~1.07) | 0.791 (0.70~1.03) |
| 512 | 0.950 | 0.901 |
| 1024 | 0.941 | 0.915 |
| 2048 | 0.967 | 0.953 |

- 4 layer까지 일정하다: `(lat(4 layer) − lat(1 layer)) / 3`으로 낸 비율이 a와 거의 같다.

| 안 본 model 크기 예측 | 비율 오차 평균 (최대) | 32 layer latency로 환산한 오차 평균 (최대) |
|---|---|---|
| a 상수 (다른 크기 평균) | 0.045 (0.17) | 4.7% (22%) |
| a 상수 (같은 seq의 다른 크기 평균) | 0.041 (0.19) | 4.3% (18%) |
| a 선형 (layer latency, weight bytes, flops, seq) | 0.036 (0.14) | 3.7% (14%) |
| b 상수 | 0.068 (0.19) | 7.7% (26%) |
| b 선형 | 0.047 (0.19) | 5.2% (18%) |

- 깨지는 곳: seq 128, 그리고 비율이 1을 넘는 점 ((3584,18944,28,128,4) seq 128 1.068, (2048,5504,16,128,4) seq 2048 1.023 등). 다른 크기에서 배울 수 없다.
- b가 a보다 예측하기 어렵다: seq 128에서 weight 반복 효과가 lat(1 layer)의 15~17%라 b의 분모가 크기마다 다르게 커진다.

## Step 5 model latency (`jobs_step5.txt` → `data_model_tpu_v4.txt` 48행, 실패 0; `analyze_model.py` → `analyze_model.log`)

- embedding latency 8~122 µs. **head latency 1B 1098, 3B 1641, 8B 2183 µs**. lm_head M=1의 대역폭이 절반으로 떨어지는 구간(vocab 128256)이 그대로 보인다.
  (embedding + head) / model latency = 1B seq 128 35%, 8B seq 2048 1.5%.
- 8B seq 2048 model latency 151.8 ms (unroll) / 152.5 ms (scan).

| 예측 / 측정 model latency, 오차 (최대) | layer latency × n | 쌓은 latency 예측 (k=1) | 측정 N layer latency 사용 |
|---|---|---|---|
| unroll (12점) | 6.1% (13%) | **2.0% (5.1%)** | 0.9% (4.4%) |
| scan (12점) | 6.4% (16%) | 9.1% (20%) | 0.07% (0.3%) |

- scan의 쌓은 latency 예측이 나쁜 것은 Step 3처럼 k=1이라서다 (k=3이면 lat(n layer) 오차 0.2% 수준).
- unroll의 "측정 N layer latency 사용"에서 1B seq 2048만 +4.4% (model latency가 embedding + lat(16 layer) + head보다 1.4 ms 짧다), 3B seq 1024 +2.5%. 나머지 ≤ 0.7%.
  마지막 layer를 마지막 token 1행으로 줄이는 최적화는 없다 (`check_lastlayer.log`: HLO에 `bf16[1,INTER]` 0회). 원인은 확인하지 못했다.

## Step 6 shape만으로 예측한 model latency (`analyze_model.log` 끝)

`예측 model latency = embedding latency + 예측 layer latency × (1 + (n − 1) × 예측 추가 layer 비율) + head latency`.
예측 layer latency = Module 2 VM의 `data_layerpred_tpu_v4.txt` `l1_pred_us` (shape만으로 예측, 안 본 model 크기). 예측 추가 layer 비율 = Step 4의 안 본 model 크기 예측. embedding·head latency는 측정값.

| 오차 (최대), 12점 | unroll | scan |
|---|---|---|
| **예측 layer latency · 예측 비율 b 선형 (shape만으로 예측)** | **7.2% (20%)** | 9.0% (17%) |
| 예측 layer latency · 예측 비율 b 상수 | 9.9% (26%) | 9.2% (19%) |
| 예측 layer latency · 예측 비율 a 선형 (기준이 안 맞는 짝) | 10.5% (33%) | 7.0% (26%) |
| 측정 layer latency · 예측 비율 b 선형 | 4.3% (9.7%) | 7.6% (19%) |
| 측정 layer latency · 측정 비율 b | 1.9% (5.2%) | 9.2% (22%) |

- unroll 7.2%의 분해: 비율 예측이 1.9 → 4.3% (+2.4%p), layer latency 예측이 4.3 → 7.2% (+2.9%p).
- 가장 나쁜 곳: 8B seq 128 (+20%), 3B seq 128 (+13%). seq 128에서 예측 비율과 예측 layer latency(Module 2 seq 128 오차 12.5%)가 같은 쪽으로 틀린다.
  seq ≥ 512만: 오차 5.4% (−11~+6%).
- scan은 맞지 않는다. 추가 layer 비율을 unroll로만 쟀고, scan은 2 layer가 튀는 구조라 이 식과 맞지 않는다 (scan용 비율은 재지 않았다).
